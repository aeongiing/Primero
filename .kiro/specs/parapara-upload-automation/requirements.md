# Requirements Document

## Introduction

**파라파라(ParaPara)** 는 빈티지·중고 의류 판매자를 위한 멀티 플랫폼 업로드 자동화 웹 서비스입니다. 판매자가 파라파라에 의류 상품을 한 번 등록하면, 시스템이 사진 정리·AI 상세정보 작성·썸네일 보정·컨디션 표시를 수행하고, 해당 상품을 번개장터·fruits·차란·당근 등 여러 중고 거래 플랫폼에 자동으로 등록합니다.

파라파라에 등록된 상품 데이터가 단일 진실 공급원(Single Source of Truth)이 되며, 각 외부 플랫폼의 상품은 이 표준 상품 데이터로부터 복제됩니다. 또한 시스템은 업로드 후 일정 기간 미판매 시 자동 할인, 한 플랫폼에서 판매 완료 시 타 플랫폼 자동 내림(동기화)을 수행합니다.

이 문서는 MVP 범위의 핵심 기능과 추후 개발 기능(Google OAuth 회원가입, ebay 연동)에 대한 요구사항을 EARS 패턴과 INCOSE 품질 규칙에 따라 정의합니다.

기술 스택: Next.js(프론트엔드), FastAPI(백엔드) + DB, AWS S3(사진 저장), AWS Rekognition / K-Fashion(카테고리·색상 자동 분류), Claude API(상세설명·모델명 추론), OpenClaw(플랫폼 자동화), Google OAuth(인증).

## Glossary

- **파라파라_시스템 (ParaPara_System)**: 본 서비스 전체를 지칭하는 최상위 시스템.
- **판매자 (Seller)**: 파라파라를 통해 중고 의류를 등록·판매하는 사용자.
- **표준_상품 (Canonical_Product)**: 파라파라에 저장된 단일 진실 공급원 상품 데이터. 상품명, 가격, 컨디션, 사이즈, 색상, 카테고리, 사진 등을 포함.
- **외부_플랫폼 (External_Platform)**: 상품이 복제·등록되는 외부 중고 거래 서비스(번개장터, fruits, 차란, 당근, 추후 ebay).
- **사진_정렬_모듈 (Photo_Ordering_Module)**: 사진을 정해진 순서(앞, 확대, 뒤, 디테일, 오염, 태그)로 정렬하는 기능 모듈.
- **이미지_분석_엔진 (Image_Analysis_Engine)**: AWS Rekognition / K-Fashion 모델을 사용해 카테고리·색상을 자동 분류하는 엔진.
- **설명_생성_엔진 (Description_Generation_Engine)**: Claude API를 사용해 상품 상세 설명과 후킹 멘트를 생성하는 엔진.
- **모델명_탐색_엔진 (Model_Lookup_Engine)**: 사진과 입력 정보를 바탕으로 의류 모델명을 추론하는 엔진.
- **이미지_보정_엔진 (Image_Retouch_Engine)**: 썸네일의 배경 제거(누끼)와 밝기·색감 보정(뽀샤시)을 수행하는 엔진.
- **컨디션_모듈 (Condition_Module)**: 상품 컨디션을 10점 만점으로 표시·수정하는 모듈.
- **플랫폼_매핑_엔진 (Platform_Mapping_Engine)**: 표준_상품 데이터를 각 외부_플랫폼의 필수 필드·카테고리 스키마로 변환하는 엔진.
- **업로드_자동화_엔진 (Upload_Automation_Engine)**: OpenClaw를 통해 외부_플랫폼에 상품을 자동 등록하는 엔진.
- **할인_스케줄러 (Discount_Scheduler)**: 미판매 기간 경과 시 자동 할인을 적용하는 모듈.
- **판매_동기화_모듈 (Sale_Sync_Module)**: 판매 완료 상태를 폴링하고 타 플랫폼에서 상품을 내리는 모듈.
- **상세페이지_UI (Detail_Page_UI)**: 파라파라 내 상품 상세페이지(Fruits 벤치마킹).
- **인증_모듈 (Auth_Module)**: Google OAuth 기반 회원가입·로그인 모듈.
- **시크릿_관리_모듈 (Secret_Management_Module)**: API 키 등 비밀 정보를 환경변수/시크릿 저장소에서 안전하게 로드하는 모듈.
- **누끼 (Background_Removal)**: 상품 사진에서 배경을 제거하는 처리.
- **후킹_멘트 (Hook_Phrase)**: 구매를 유도하기 위한 광고성 문구.
- **컨디션_점수 (Condition_Score)**: 0~10 범위의 정수 또는 0.5 단위 값으로 표현되는 상품 상태 점수.

## Requirements

### Requirement 1: 사진 업로드 및 저장

**User Story:** 판매자로서, 나는 상품 사진을 업로드하여 클라우드에 안전하게 저장하고 싶다. 그래야 이후 정렬·분석·보정에 사용할 수 있다.

#### Acceptance Criteria

1. WHEN 판매자가 하나 이상의 이미지 파일을 업로드하면, THE 파라파라_시스템 SHALL 각 이미지를 AWS S3에 저장하고 각 이미지의 저장 URL을 반환한다.
2. WHEN 이미지 저장이 완료되면, THE 파라파라_시스템 SHALL 저장된 이미지를 해당 표준_상품에 연결한다.
3. IF 업로드된 파일의 확장자가 jpg, jpeg, png, webp 중 하나가 아니면, THEN THE 파라파라_시스템 SHALL 업로드를 거부하고 허용 확장자 목록을 포함한 오류 메시지를 반환한다.
4. IF 업로드된 파일 크기가 10MB를 초과하면, THEN THE 파라파라_시스템 SHALL 저장 시도 후 업로드를 거부하고 최대 허용 크기를 포함한 오류 메시지를 반환한다.
5. IF S3 저장에 실패하면, THEN THE 파라파라_시스템 SHALL 오류 코드를 반환하고 해당 이미지를 표준_상품에 연결하지 않는다.

### Requirement 2: 사진 정렬

**User Story:** 판매자로서, 나는 상품 사진을 정해진 순서(앞, 확대, 뒤, 디테일, 오염, 태그)로 정렬하고 싶다. 그래야 구매자에게 일관된 순서로 상품을 보여줄 수 있다.

#### Acceptance Criteria

1. THE 사진_정렬_모듈 SHALL 사진 역할을 앞, 확대, 뒤, 디테일, 오염, 태그 6개 범주로 구분한다.
2. WHEN 판매자가 특정 사진의 역할을 선택하면, THE 사진_정렬_모듈 SHALL 해당 사진을 선택된 역할에 배정한다.
3. WHEN 판매자가 사진 정렬을 저장하면, THE 사진_정렬_모듈 SHALL 사진들을 앞, 확대, 뒤, 디테일, 오염, 태그 순서로 정렬하여 표준_상품에 저장한다.
4. WHERE 동일한 역할에 여러 사진이 배정된 경우, THE 사진_정렬_모듈 SHALL 판매자가 지정한 역할 내 순서를 유지한다.
5. WHEN 판매자가 정렬 저장을 시도하는 시점에 앞 역할에 배정된 사진이 하나도 없으면, THE 사진_정렬_모듈 SHALL 정렬 저장 거부와 앞 사진 필요 오류 메시지 반환을 하나의 원자적 동작으로 함께 수행한다.

### Requirement 3: 의류 카테고리·색상 자동 분류

**User Story:** 판매자로서, 나는 업로드한 사진으로부터 의류 카테고리와 색상이 자동으로 분류되기를 원한다. 그래야 입력 수고를 줄일 수 있다.

#### Acceptance Criteria

1. WHEN 판매자가 상품 사진 업로드를 완료하면, THE 이미지_분석_엔진 SHALL 사진을 분석하여 의류 카테고리 후보와 대표 색상 후보를 생성한다.
2. WHEN 이미지_분석_엔진이 분류 결과를 생성하면, THE 파라파라_시스템 SHALL 분류된 카테고리와 색상을 표준_상품의 기본값으로 채운다.
3. THE 파라파라_시스템 SHALL 자동 분류된 카테고리와 색상을 판매자가 수정할 수 있도록 제공한다.
4. IF 이미지_분석_엔진이 분류에 실패하면, THEN THE 파라파라_시스템 SHALL 카테고리와 색상을 빈 값으로 두고 판매자에게 수동 입력을 요청한다.

### Requirement 4: AI 상세정보 자동 작성

**User Story:** 판매자로서, 나는 상품 상세 설명과 후킹 멘트가 AI로 자동 작성되기를 원한다. 그래야 매력적인 판매글을 빠르게 만들 수 있다.

#### Acceptance Criteria

1. WHEN 판매자가 상세정보 자동 작성을 요청하면, THE 설명_생성_엔진 SHALL Claude API를 사용하여 상품명, 컨디션, 사이즈, 색상, 카테고리를 입력으로 상품 상세 설명을 생성한다.
2. THE 설명_생성_엔진 SHALL 생성된 상세 설명에 하나 이상의 후킹_멘트를 포함한다.
3. THE 파라파라_시스템 SHALL 생성된 상세 설명을 판매자가 수정할 수 있도록 제공한다.
4. IF 설명_생성_엔진의 호출이 실패하면, THEN THE 파라파라_시스템 SHALL 오류 메시지를 반환하고 판매자가 설명을 직접 입력할 수 있도록 한다.
5. WHEN 설명_생성_엔진이 Claude API를 호출할 때, THE 설명_생성_엔진 SHALL API 키를 시크릿_관리_모듈로부터 조회한다.

### Requirement 5: 옷 모델명 찾기 (선택 기능)

**User Story:** 판매자로서, 나는 사진과 입력 정보로부터 의류 모델명을 추론받고 싶다. 그래야 정확한 상품명을 작성할 수 있다.

#### Acceptance Criteria

1. WHERE 모델명 찾기 기능이 활성화된 경우, WHEN 판매자가 모델명 추론을 요청하면, THE 모델명_탐색_엔진 SHALL 사진과 입력 정보를 바탕으로 모델명 후보 목록을 생성한다.
2. WHERE 모델명 찾기 기능이 활성화된 경우, THE 모델명_탐색_엔진 SHALL 각 모델명 후보에 대해 신뢰도 점수를 함께 제공한다.
3. THE 파라파라_시스템 SHALL 모델명 후보를 판매자가 선택하거나 직접 수정할 수 있도록 제공한다.
4. IF 모델명_탐색_엔진이 후보를 하나도 생성하지 못하면, THEN THE 파라파라_시스템 SHALL 후보가 없음을 알리고 판매자가 모델명을 직접 입력하도록 한다.

### Requirement 6: 썸네일 사진 보정

**User Story:** 판매자로서, 나는 썸네일 사진의 배경을 제거하고 밝기·색감을 보정받고 싶다. 그래야 상품이 더 돋보이게 보일 수 있다.

#### Acceptance Criteria

1. WHEN 판매자가 썸네일 보정을 요청하면, THE 이미지_보정_엔진 SHALL 선택된 사진에서 배경을 제거(누끼)한 결과 이미지를 생성한다.
2. WHEN 누끼 처리가 성공적으로 완료되면, THE 이미지_보정_엔진 SHALL 결과 이미지에 밝기·색감 보정(뽀샤시)을 적용한다.
3. IF 누끼 처리 중 실패가 발생하면, THEN THE 이미지_보정_엔진 SHALL 밝기·색감 보정 단계를 수행하지 않는다.
4. WHEN 판매자가 썸네일 보정 기능에 진입하면, THE 이미지_보정_엔진 SHALL 처리 진행 여부와 무관하게 보정 이미지용 별도 저장 위치를 AWS S3에 즉시 마련한다.
5. THE 이미지_보정_엔진 SHALL 보정된 이미지를 원본 이미지와 별도의 저장 위치에 저장한다.
6. THE 파라파라_시스템 SHALL 보정된 이미지와 원본 이미지를 판매자가 비교하여 선택할 수 있도록 제공한다.
7. IF 이미지_보정_엔진의 처리가 실패하면, THEN THE 파라파라_시스템 SHALL 오류 메시지를 반환하고 원본 이미지를 썸네일로 유지한다.

### Requirement 7: 컨디션 점수 표시 및 수정

**User Story:** 판매자로서, 나는 상품 컨디션을 10점 만점으로 표시하고 직접 수정하고 싶다. 그래야 상품 상태를 명확하게 전달할 수 있다.

#### Acceptance Criteria

1. THE 컨디션_모듈 SHALL 컨디션_점수를 0점 이상 10점 이하 범위로 표시한다.
2. WHEN 판매자가 컨디션_점수를 변경하면, THE 컨디션_모듈 SHALL 변경된 값을 표준_상품에 저장한다.
3. IF 판매자가 0 미만 또는 10 초과의 컨디션_점수를 입력하면, THEN THE 컨디션_모듈 SHALL 입력을 거부하며, 오류 메시지 생성 실패와 무관하게 입력 거부를 수행한다.
4. THE 컨디션_모듈 SHALL 컨디션에 대한 메모(예: 얼룩 위치)를 판매자가 입력할 수 있도록 제공한다.

### Requirement 8: 표준 상품 데이터 입력

**User Story:** 판매자로서, 나는 상품명·가격·사이즈·컨디션 등 핵심 정보를 입력하여 표준 상품을 생성하고 싶다. 그래야 모든 플랫폼 등록의 기준 데이터가 마련된다.

#### Acceptance Criteria

1. THE 파라파라_시스템 SHALL 판매자가 상품명, 가격, 컨디션_점수, 사이즈(표기 사이즈, 가슴단면, 총장)를 입력할 수 있도록 제공한다.
2. WHEN 판매자가 표준_상품을 저장하면, THE 파라파라_시스템 SHALL 입력된 데이터를 단일 진실 공급원으로 데이터베이스에 저장한다.
3. IF 상품명 또는 가격이 비어 있으면, THEN THE 파라파라_시스템 SHALL 저장을 거부하고 누락된 필수 항목을 포함한 오류 메시지를 반환한다.
4. IF 가격이 0 이하의 값이면, THEN THE 파라파라_시스템 SHALL 저장을 거부하고 가격은 양수여야 한다는 오류 메시지를 반환한다.
5. WHEN 표준_상품이 갱신되면, THE 파라파라_시스템 SHALL 해당 표준_상품을 단일 진실 공급원으로 유지하여 외부_플랫폼 복제의 기준으로 사용한다.

### Requirement 9: 플랫폼 필드 매핑

**User Story:** 판매자로서, 나는 표준 상품 데이터가 각 플랫폼의 필수 필드와 카테고리 체계로 자동 변환되기를 원한다. 그래야 플랫폼별로 다른 입력 양식을 일일이 맞추지 않아도 된다.

#### Acceptance Criteria

1. WHEN 판매자가 특정 외부_플랫폼으로의 등록을 요청하면, THE 플랫폼_매핑_엔진 SHALL 표준_상품 데이터를 해당 외부_플랫폼의 필수 필드 스키마로 변환한다.
2. THE 플랫폼_매핑_엔진 SHALL 표준_상품의 카테고리를 각 외부_플랫폼의 카테고리 트리에 정의된 항목으로 매핑한다.
3. THE 플랫폼_매핑_엔진 SHALL 표준_상품의 컨디션_점수를 각 외부_플랫폼의 컨디션 등급 체계로 매핑한다.
4. THE 플랫폼_매핑_엔진 SHALL 표준_상품의 색상, 사이즈, 계절, 패턴, 소재, 스타일, 핏감 필드를 각 외부_플랫폼이 지원하는 값 목록으로 매핑한다.
5. WHERE 외부_플랫폼이 계절 또는 소재에 대해 최대 선택 개수를 제한하는 경우, THE 플랫폼_매핑_엔진 SHALL 매핑 결과를 해당 플랫폼의 최대 선택 개수 이하로 제한한다.
6. IF 표준_상품의 어떤 필드 값이 대상 외부_플랫폼의 허용 값 목록에 매핑되지 않으면, THEN THE 플랫폼_매핑_엔진 SHALL 해당 필드를 매핑 불가로 표시하고 판매자에게 수동 선택을 요청한다.
7. IF 대상 외부_플랫폼의 필수 필드가 매핑 후에도 비어 있으면, THEN THE 플랫폼_매핑_엔진 SHALL 등록을 보류하고, 다른 시스템 오류 발생 여부와 무관하게 항상 누락된 필수 필드 목록을 반환한다.

### Requirement 10: 멀티 플랫폼 업로드 자동화

**User Story:** 판매자로서, 나는 표준 상품을 번개장터·fruits·차란·당근에 자동으로 등록하고 싶다. 그래야 플랫폼마다 수동으로 올리는 수고를 없앨 수 있다.

#### Acceptance Criteria

1. WHEN 판매자가 선택한 외부_플랫폼 목록에 대해 업로드를 요청하면, THE 업로드_자동화_엔진 SHALL OpenClaw를 통해 각 외부_플랫폼에 매핑된 상품 데이터를 등록한다.
2. WHEN 특정 외부_플랫폼에 등록이 성공하면, THE 업로드_자동화_엔진 SHALL 해당 외부_플랫폼의 상품 식별자를 표준_상품에 연결하여 저장한다.
3. IF 특정 외부_플랫폼에 등록이 실패하면, THEN THE 업로드_자동화_엔진 SHALL 실패한 플랫폼과 실패 사유를 기록하고 나머지 플랫폼의 등록을 계속 진행한다.
4. THE 업로드_자동화_엔진 SHALL 각 외부_플랫폼별 등록 상태(성공, 실패, 진행 중)를 판매자에게 표시한다.

### Requirement 11: 미판매 자동 할인

**User Story:** 판매자로서, 나는 등록 후 일주일 동안 팔리지 않은 상품의 가격이 모든 플랫폼에서 자동으로 할인되기를 원한다. 그래야 판매 가능성을 높일 수 있다.

#### Acceptance Criteria

1. WHEN 표준_상품이 모든 대상 외부_플랫폼에 등록된 시점으로부터 7일이 경과하고 해당 표준_상품이 미판매 상태이면, THE 할인_스케줄러 SHALL 표준_상품 가격을 직전 가격 대비 10% 인하한다.
2. WHEN 할인_스케줄러가 가격을 인하하면, THE 업로드_자동화_엔진 SHALL 인하된 가격을 등록된 모든 외부_플랫폼에 반영한다.
3. WHEN 할인_스케줄러가 가격을 인하하면, THE 할인_스케줄러 SHALL 인하된 가격을 표준_상품에 저장한다.
4. IF 표준_상품이 이미 판매 완료 상태이면, THEN THE 할인_스케줄러 SHALL 해당 표준_상품에 할인을 적용하지 않는다.

### Requirement 12: 판매 완료 동기화

**User Story:** 판매자로서, 나는 한 플랫폼에서 상품이 팔리면 다른 모든 플랫폼에서 자동으로 내려가기를 원한다. 그래야 중복 판매를 방지할 수 있다.

#### Acceptance Criteria

1. THE 판매_동기화_모듈 SHALL 등록된 각 외부_플랫폼의 상품 판매 상태를 주기적으로 폴링한다.
2. WHEN 판매_동기화_모듈이 특정 외부_플랫폼에서 표준_상품의 판매 완료를 감지하면, THE 판매_동기화_모듈 SHALL 해당 표준_상품을 판매 완료 상태로 갱신한다.
3. WHEN 표준_상품의 판매 완료 상태 갱신이 성공적으로 확정되면, THE 업로드_자동화_엔진 SHALL 판매가 발생한 플랫폼을 제외한 나머지 모든 외부_플랫폼에서 해당 상품을 내린다.
4. IF 특정 외부_플랫폼에서 상품 내림이 실패하면, THEN THE 판매_동기화_모듈 SHALL 실패한 플랫폼과 사유를 기록하고 재시도 대상으로 표시한다.

### Requirement 13: 상품 상세페이지

**User Story:** 판매자와 구매자로서, 나는 파라파라 내에서 상품 상세페이지를 보고 싶다. 그래야 상품 정보를 한눈에 확인할 수 있다.

#### Acceptance Criteria

1. WHEN 사용자가 표준_상품의 상세페이지를 요청하면, THE 상세페이지_UI SHALL 정렬된 사진, 상품명, 가격, 컨디션_점수, 사이즈 정보, 상세 설명을 표시한다.
2. THE 상세페이지_UI SHALL 사진을 사진_정렬_모듈이 저장한 순서(앞, 확대, 뒤, 디테일, 오염, 태그)로 표시한다.
3. WHERE 표준_상품에 보정된 썸네일이 존재하는 경우, THE 상세페이지_UI SHALL 목록 화면에서 보정된 썸네일을 대표 이미지로 표시한다.

### Requirement 14: API 키 및 비밀 정보 보안

**User Story:** 운영자로서, 나는 Claude API 키 등 비밀 정보가 소스 코드에 노출되지 않고 안전하게 관리되기를 원한다. 그래야 키 유출 위험을 방지할 수 있다.

#### Acceptance Criteria

1. THE 시크릿_관리_모듈 SHALL Claude API 키를 환경변수 또는 시크릿 저장소로부터 로드한다.
2. THE 파라파라_시스템 SHALL API 키 및 비밀 정보를 소스 코드 저장소에 평문으로 포함하지 않는다.
3. IF 필요한 API 키가 환경변수 또는 시크릿 저장소에 설정되어 있지 않으면, THEN THE 시크릿_관리_모듈 SHALL 명확한 설정 누락 오류를 반환하고 관련 외부 API 호출을 차단하되, 이후 시크릿이 설정되면 재시도와 설정 재로드를 허용한다.
4. THE 파라파라_시스템 SHALL 로그 및 오류 메시지에 API 키 값을 출력하지 않는다.

### Requirement 15: Google OAuth 회원가입 및 온보딩 (추후 개발)

**User Story:** 판매자로서, 나는 Google 계정으로 간편하게 회원가입하고 온보딩 안내를 받고 싶다. 그래야 빠르게 서비스를 시작할 수 있다.

#### Acceptance Criteria

1. WHEN 사용자가 Google 계정으로 로그인을 요청하면, THE 인증_모듈 SHALL Google OAuth 인증 절차를 수행한다.
2. WHEN Google OAuth 인증이 성공하면, THE 인증_모듈 SHALL 사용자 계정을 생성하거나 기존 계정으로 로그인 세션을 발급한다.
3. WHEN 신규 사용자가 처음 로그인하면, THE 파라파라_시스템 SHALL 온보딩 화면을 표시한다.
4. IF Google OAuth 인증이 실패하면, THEN THE 인증_모듈 SHALL 로그인을 거부하고 인증 실패 메시지를 반환한다.

### Requirement 16: ebay 플랫폼 연동 (추후 개발)

**User Story:** 판매자로서, 나는 ebay에도 상품을 자동 등록하고 싶다. 그래야 해외 구매자에게도 상품을 노출할 수 있다.

#### Acceptance Criteria

1. WHERE ebay 연동이 활성화된 경우, THE 플랫폼_매핑_엔진 SHALL 표준_상품 데이터를 ebay의 빈티지 의류 카테고리 및 컨디션(New with box, New without box, New with defects, Pre-owned - Excellent, Pre-owned - Good, Pre-owned - Fair) 체계로 매핑한다.
2. IF ebay 매핑이 상품 정보 누락 또는 ebay API 오류로 실패하면, THEN THE 플랫폼_매핑_엔진 SHALL 해당 상품을 ebay에 대해 미매핑 상태로 두고 다른 외부_플랫폼 작업을 계속 진행한다.
3. WHERE ebay 연동이 활성화된 경우, WHEN 판매자가 ebay 등록을 요청하면, THE 업로드_자동화_엔진 SHALL 매핑된 상품 데이터를 ebay에 등록한다.
4. WHERE ebay 연동이 활성화된 경우, THE 판매_동기화_모듈 SHALL ebay의 판매 상태를 폴링 대상에 포함한다.
