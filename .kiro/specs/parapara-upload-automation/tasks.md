# Implementation Plan: 파라파라(ParaPara) 업로드 자동화

## Overview

본 계획은 설계 문서의 **단일 진실 공급원(SSOT)** 원칙에 따라 표준_상품을 중심으로 기능을 점진적으로 구현한다. 백엔드는 FastAPI(Python) + PostgreSQL + AWS S3, 프론트엔드는 Next.js(TypeScript)로 구현하며, 외부 서비스(S3, Rekognition/K-Fashion, Claude, OpenClaw)는 어댑터로 캡슐화하고 테스트에서는 모킹한다.

개발 순서는 기획 문서의 권장 순서를 따른다: 기반/시크릿 → API 스펙 → 사진 업로드 → AI 분석/설명 → 썸네일 보정 → 상품 등록 API → 프론트 업로드 → 매핑 → OpenClaw 자동 등록 → 판매 동기화 → 미판매 할인 → 사진 정렬 UI.

테스트 전략:
- **속성 기반 테스트(PBT)**: 설계의 16개 Correctness Property를 검증. 백엔드 순수 로직은 **Hypothesis**, 프론트엔드 순수 로직은 **fast-check** 사용. 각 PBT는 **최소 100회** 이상 생성 입력으로 실행하고, 주석으로 `Feature: parapara-upload-automation, Property {번호}` 형식의 태그를 단다.
- **단위/통합/스냅샷 테스트**: 엣지·실패 주입·외부 연동 와이어링·UI 렌더링 검증.
- `*`로 표시된 하위 작업은 선택 사항(테스트)이며 MVP 가속을 위해 건너뛸 수 있다.

## Notes

- `*`로 표시된 하위 작업은 선택 사항(단위·속성·통합·스냅샷 테스트)이며 빠른 MVP를 위해 건너뛸 수 있다. 핵심 구현 작업은 절대 선택으로 표시하지 않는다.
- 각 작업은 추적성을 위해 특정 요구사항 절 번호를 참조한다.
- 16개 Correctness Property 전부에 대해 PBT 작업을 배치했다(백엔드 Hypothesis 16개 + 프론트 fast-check 미러 3개). 모든 속성 테스트는 최소 100회 이상 생성 입력으로 실행한다.
- 속성 테스트는 구현 직후에 배치하여 오류를 조기에 잡는다.
- 외부 서비스(S3, Rekognition, Claude, OpenClaw)는 어댑터로 캡슐화하고 테스트에서 모킹한다.
- 시크릿 관리(env var 로딩, 평문 키 금지)는 기반 작업(1.2)으로 가장 먼저 구현한다.
